Tier 2 — Iterative Feedback Loop

Autonomy + Live Inspection
🔄 execute-and-fix-tests
/execute-and-fix-tests

The most agentic skill in the project. Runs Playwright tests, parses failures, live-inspects the running application via the Playwright MCP browser to confirm actual DOM state, applies targeted code fixes, and re-runs. Repeats up to 3 total executions (1 initial + 2 fix iterations). With --ado-check, it also fetches ADO Test Case steps and detects contradictions between documented behavior and live app reality — pausing to ask the user only when a genuine conflict is found.

🔁 Iterative Loop (3x) 📡 MCP Live Browser 🌐 ADO REST API 🧠 Contradiction Detection ⚙️ Auto-fix
Step 0 — Read .env config → Step 1 — Resolve scope → Step 2 — Initial test run → Step 3 — Parse failures → Step 3.5 — Fetch ADO steps (--ado-check) → Step 4 — Live MCP inspection → Step 5 — Classify & plan fixes → Step 5.5 — Ask user if CONTRADICTION → Step 6 — Apply fixes → Step 7 — Re-run ↩ (loop max 2x) → Step 8 — Tag blocked as test.fixme → Step 9 — Final summary
  • Never guesses selectors — always navigates the live app and takes a DOM snapshot before writing any fix
  • Classifies failures into 10 categories (LOCATOR, TEXT, ASSERTION, METHOD-MISSING, NAVIGATION, TIMING, AUTH, COMPILE…)
  • ADO contradiction check: cross-references ADO TC expected result vs. live app — the only mandatory pause point
  • After 3 executions, marks unresolved tests with test.fixme + FIXME comment instead of guessing further
  • Uses MCP tools: browser_snapshot, browser_click, browser_console_messages, browser_network_requests

Tier 4 — Multi-Task Autonomous Processors

Parallel Task Execution
✨ polish-generated-code
/polish-generated-code

Six-task autonomous cleanup pipeline that runs over all generated files without user input. Each task targets a specific class of AI code-generation artifact: syntax errors, method ordering, inline locator violations, missing implementations, hallucinated API calls, and dead imports.

⚙️ 6 Sequential Tasks 🔍 Cross-file Analysis 🧠 Implementation Gen ✅ Verified Output
  • Task 1: Remove stray backslash-escapes before opening string quotes in spec files
  • Task 2: Re-order page methods — all action methods first, then all assertion methods
  • Task 3: Extract inline page.locator() calls into the locator repository file
  • Task 4: Implement missing page-object methods called from specs (real code, not stubs)
  • Task 5: Detect and correct hallucinated AdvancedActionsHelper / AdvancedAssertionsHelper method names
  • Task 6: Remove unused import statements from all generated page and spec files

/merge-tc-sets

Merges two independently-generated TC sets (e.g. Claude + OpenAI) for the same feature, deduplicates them, performs an AI-driven gap analysis to find missing coverage, and auto-assigns tier tags (@Smoke, @Regression, @automation) to every TC. Optionally enriches gap analysis with live wireframe context via MCP.

🧠 Gap Analysis AI 🌐 ADO TC Fetch 🏷️ Auto-tagging 🔍 Wireframe MCP
  • Auto-detects FileA and FileB from test_cases/ — no arguments required
  • Fetches existing ADO TC IDs to avoid duplicating already-pushed test cases
  • Gap analysis evaluates 7 coverage dimensions: Positive, Negative, Boundary, Security, Performance, DB, API
  • Auto-assigns @Smoke or @Regression and marks automation-suitable TCs with @automation
  • Output is ready to pipe directly into /tcs-to-ado and /tcs-to-plscript
