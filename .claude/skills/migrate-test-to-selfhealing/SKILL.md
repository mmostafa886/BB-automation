## ARCHITECTURE CONTEXT

### Old Test Pattern (BEFORE)

```typescript
import { test, expect } from '@playwright/test';

test.describe('Module - Test title', () => {
  test('TC-XXXX: title', async ({ page }) => {
    // Step N: description
    await page.goto('/path');
    await page.locator('selector').click();
    await expect(page.locator('selector')).toBeVisible();
  });
});
```

### Self-Healing Test Pattern (AFTER)

**CRITICAL: No `test.step()` calls in test bodies.**
Steps are tracked automatically by `StepRunner.step()` inside `AdvancedActionsHelper`
and `AdvancedAssertionsHelper`. Each `pomSelfHealing.<page>.<method>()` call already
produces a named step in the Playwright HTML report. Adding extra `test.step()` wrappers
would create redundant nesting — do NOT add them.

```typescript
/**
 * Auto-generated Playwright TypeScript test from Azure Test Plan
 *
 * @testcase TC-XXXX
 * @title <title>
 * @module <Module>
 * @area <Area>
 * @priority <N>
 * @tags <tags>
 *
 * @generated <ISO timestamp>
 * @revision 1
 */

import { test } from '../../fixtures/self-healing-fixture';

test.describe('<Module> - <title>', () => {
  test('TC-XXXX: <title> @<module-tag>', async ({ selfHealingFixture: { pomSelfHealing } }) => {

    // Step N: description
    await pomSelfHealing.<pageProp>.<actionMethod>();

    // Step N+1: description
    await pomSelfHealing.<pageProp>.<assertionMethod>();
  });
});
```

### Fixture Import Path

Always: `import { test } from '../../fixtures/self-healing-fixture';`

(Two levels up from `tests/generated/<Module>/`)

## STEP-BY-STEP PROCESS

### Step 0 — Determine Scope

If no input is provided (or input is `all`):

```bash
find tests/ -name "*.spec.ts" -o -name "*.spec.js" | sort
```

Collect all spec files. Already-migrated files (detected in Step 2) are skipped inline.
For each target spec file, execute Steps 1–7.

### Step 1 — Read the Source File

```bash
cat <spec-file-path>
```

Extract:
- TC ID, title, module, area, priority
- All test steps (comments + action lines)
- The fixture pattern used (old `{ page }` or already migrated)

### Step 2 — Check Migration Status

If the file already imports from `self-healing-fixture`, print:
`"<filename>: ALREADY MIGRATED — skipping."`
and skip to the next file.

### Step 3 — Build the Method Lookup Table

For every page touched in the test, read the already-created page object:

```bash
cat src/pages/<page>-page-self-healing.ts
```

Extract all public `async` method signatures. Build a **semantic** lookup table — not
just an exact-name map, but an intent map that includes the selectors / locator keys each
method interacts with and what it does (action, assertion, or combined action+assertion):

```
intentKeywords / locatorKeys touched → methodName → type (action | assert | combined)
```

**Similarity rule:** A method that clicks a button AND verifies the result (e.g.
`clickSaveButtonAndVerifySuccess`) covers **both** a raw `click` call AND the subsequent
`expect(...).toBeVisible()` on the result element. One sequential group of raw calls that
share the same intent can collapse into a single page method call.

When matching a raw locator call to a page method, use this priority:
1. **Exact locator key match** — the raw selector string matches one in `src/locators/`,
   and the page class has a method that uses that locator key.
2. **Semantic intent match** — the step comment or surrounding context implies the same
   intent as a page method name (e.g. step says "Deactivate a reagent" →
   `deactivateReagent()` even if the raw selector differs).
3. **Partial coverage** — if one page method covers multiple consecutive raw lines
   (action + assertion), replace all those lines with the single method call.

### Step 4 — Replace Direct Locator Usage with Page Methods

For each raw Playwright call in the test, apply the lookup:

| Raw call | Replace with |
|----------|-------------|
| `page.goto('/path')` | `pomSelfHealing.<page>.navigateTo()` |
| `page.locator(sel).click()` | matched page method (click or combined) |
| `page.locator(sel).fill(val)` | matched page method (fill) |
| `page.locator(sel).selectOption(val)` | matched page method (select) |
| `expect(page.locator(sel)).toBeVisible()` | matched page method (verify or combined) |
| `expect(page.locator(sel)).toHaveText(t)` | matched page method (verifyText or combined) |
| `expect(page.locator(sel)).toHaveCount(n)` | matched page method (verifyCount or combined) |
| `page.waitForURL(pattern)` | `pomSelfHealing.<page>.waitForURL(pattern)` |

**If no matching page method exists (exact or semantic):**
- Add `// TODO: add <suggestedMethodName>() to <PageClass>` on the line above
- Keep the original raw line as a comment below it
- Do NOT delete test steps under any circumstances.

**Step comment lines** (`// Step N: ...`) are preserved exactly as-is — they are test
documentation. Do NOT wrap them or the following line in `test.step()`.

### Step 5 — Determine Output Path

Target directory: `tests/generated/<Module>/`
File name: preserve the original file name.

```bash
mkdir -p tests/generated/<Module>
```

### Step 6 — Write the Migrated File

Output the complete migrated TypeScript spec.
- Add the JSDoc header block with `@testcase`, `@title`, `@module`, `@area`, `@priority`,
  `@tags`, `@generated`, `@revision`
- `@generated` = current ISO timestamp
- `@tags` = `none` if no tags are present
- **MUST NOT** contain any `test.step()`, `await test.step()`, or `test.step(` calls.
  Step tracking is handled entirely by `StepRunner.step()` inside the helpers.

### Step 7 — Per-File Validation

Confirm for each migrated file:
- `import { test }` from `../../fixtures/self-healing-fixture` (no `expect` import)
- `async ({ selfHealingFixture: { pomSelfHealing } }) =>` in the test callback
- No bare `page.` calls remain (unless wrapped in a `// TODO` comment)
- No `test.step(` calls anywhere in the test body
- Step comments are preserved verbatim
- TC ID tag is added to the test title: `@<module-lowercase>`

### Step 8 — Post-Migration Verification (MANDATORY)

After **all** files have been written, perform a final scan across every migrated file to
confirm no direct element usage or test.step wrappers remain:

```bash
grep -rn "page\.locator\|page\.goto\|expect(page\." tests/generated/ --include="*.ts"
grep -rn "await test\.step\|test\.step(" tests/generated/ --include="*.ts"
```

For each match found:
- `page.locator`, `page.goto`, `expect(page.` — acceptable **only** if the line begins
  with `//` (commented-out TODO)
- `test.step(` — **never acceptable** in a migrated test file; must be removed

Report all verification failures:

```
⚠ VERIFICATION FAILURES — direct element usage or test.step() still present:
  tests/generated/Reagents/tc-5405.spec.ts:23  →  await page.locator('.confirm-btn').click();
  tests/generated/Instruments/tc-1234.spec.ts:15  →  await test.step('Step 1', async () => {
```

For each failure:
- Direct locator → replace with the correct `pomSelfHealing.<page>.<method>()` call or a
  `// TODO:` stub
- `test.step(` wrapper → unwrap: keep the inner content but remove the `test.step()`
  call and its callback wrapper

Re-run the verification grep after fixes until zero failures remain.

### Step 9 — Final Summary

Print a table:

| File | Steps Mapped | TODOs Remaining | Verification | Status |
|------|-------------|-----------------|--------------|--------|
| `tests/generated/<Module>/<file>.spec.ts` | N | M | ✅ PASS | MIGRATED |
| `tests/generated/<Module>/<file>.spec.ts` | N | 0 | ❌ FAIL | NEEDS FIX |

Print at the bottom:
```
Migration complete: <X> files migrated, <Y> files skipped (already migrated)
Verification: <P> PASS  |  <F> FAIL
```

If any failures remain, do NOT mark the run as complete. Fix them before printing the
final summary.

## RULES

1. **Never remove steps** — if a step can't be mapped, comment it out with `// TODO:`.
2. **Preserve step comments verbatim** — they are the test documentation.
3. **No `expect` imports** — the self-healing fixture provides assertions via the page objects.
4. **Keep TC ID in the test title** — `test('TC-XXXX: ...', ...)`.
5. **Module tag on test title** — append `@<module>` (lowercase, no spaces) at the end.
6. **One spec → one `test()` block** — do not split or merge tests.
7. **Do not add new steps** — only migrate existing ones.
8. **JSDoc header is mandatory** — include it even if the original spec lacked it.
9. **If the page object method doesn't exist**, add `// TODO: add <method> to <PageClass>` and
   keep the original interaction as a comment below it.
10. **Post-migration verification is mandatory** — always run Step 8 after all files are written.
    No run is complete until both verification greps return zero uncommented failures.
11. **NEVER use `test.step()` in migrated test files** — remove any existing `test.step()`
    wrappers found in the source. All step wrapping is handled internally by
    `StepRunner.step()` inside `AdvancedActionsHelper` and `AdvancedAssertionsHelper`.
    Tests must call page object methods directly.

### Input (old):

  test('TC-5405: Verify the reagents deactivation', async ({ page }) => {

    // Step 1: Navigate to the reagents page
    await page.goto('/reagents');

    // Step 2: Deactivate a reagent

    // Step 3: Confirm deactivation
    await page.locator('.confirm-btn').click();

    // Step 4: Verify toast message
